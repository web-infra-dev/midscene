# 模型策略

本文介绍 Midscene 的模型选择策略。

## Midscene 的纯视觉定位

AI UI 自动化需要完成任务规划和元素定位。业界主要有两种元素定位路线：结合 DOM 与截图标注，或直接使用截图进行纯视觉定位。Midscene 采用纯视觉路线，由模型直接分析界面截图并定位目标元素。在执行 UI 操作和元素定位时，不依赖 DOM 或额外标注。

这种方式有以下特点：

- 不依赖 UI 渲染技术栈。
- 适用于浏览器 Canvas、Android、iOS 和桌面应用等不同类型的界面。
- 可以校验颜色、高亮状态和布局等用户实际看到的效果。
- 无需维护 Selector 或额外的界面标注。

纯视觉定位对模型的视觉理解能力要求较高，运行时也需要处理页面截图。对于具备完整组件树和无障碍标注的界面，基于结构信息的方案可能更节省模型资源。Midscene 选择纯视觉路线，是为了在不同平台和渲染技术之间保持一致的交互能力。

从 1.0 版本开始，Midscene 的 UI 操作与元素定位只使用纯视觉路线。在数据提取或页面理解场景中，仍可按需附带 DOM 信息。具体参数请参考 [API Reference](./reference/#extraction-location-assertion)。

## 模型职责

Midscene 始终需要一个 Default 模型。Planning 模型和 Insight 模型均为可选配置；未单独配置时，对应任务会自动使用 Default 模型。

| 模型 | 主要职责 |
| --- | --- |
| Default 模型 | 负责元素定位（Locate），以及未分配给 Planning 或 Insight 模型的任务 |
| Planning 模型 | 负责 `aiAct` 和 `ai` 的任务规划 |
| Insight 模型 | 负责 `aiQuery`、`aiAsk`、`aiAssert` 等数据提取、断言和页面理解任务 |

配置 Planning 模型或 Insight 模型后，元素定位仍由 Default 模型负责。独立模型不会替代 Default 模型。

## 何时使用多模型

大多数场景只需配置 Default 模型。当不同任务对模型能力的要求明显不同时，可以考虑增加独立模型：

- 复杂的多步骤任务需要更强的规划能力时，配置 Planning 模型。
- 数据提取、断言或页面理解需要更强的视觉问答能力时，配置 Insight 模型。
- 希望分别平衡定位、规划和页面理解的效果、延迟与成本时，为对应任务选择不同模型。

多模型配置会增加模型服务、环境变量和调用链路的复杂度，也可能增加延迟和 Token 消耗。建议先使用 Default 模型；确认问题来自规划或页面理解后，再添加对应的独立模型。

如果任务效果不理想，请先参考[模型调试与可观测性](./model-debugging-observability)定位问题。配置方法请参考[可选：配置多个模型](./model-common-config#multi-model-combination-example)。
