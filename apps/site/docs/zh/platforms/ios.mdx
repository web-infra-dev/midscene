# iOS

Midscene 通过 WebDriverAgent（WDA）连接并控制 iOS 设备，支持对原生应用、混合应用及系统界面进行自动化操作。

本文将带你完成 iOS 环境准备与设备连接，并在 Playground 中试跑一次操作与断言，为后续接入测试框架或 JavaScript SDK 做好准备。

## 效果展示

**提示词：** 打开美团，帮我下单一杯 Manner 超大杯冰美式咖啡，选择加浓、少冰，并在进入结算页面后等待确认。（[完整报告](https://lf3-static.bytednsdoc.com/obj/eden-cn/nupipfups/Midscene/1.0-showcases/meituan.html)）

## 快速开始

请先安装 Node.js（版本要求 `^20.19.0 || ^22.12.0 || >=24.0.0`），确认终端中可执行 `node -v` 和 `npx --version`，并提前准备好[模型配置](../model-api-setup)（稍后将在 Playground 中填写）。

### 准备 iOS 环境

Midscene 直接与 WebDriverAgent（WDA）服务通信。请先准备好 Mac、Xcode 与目标设备，并确保 WDA 的 `/status` 接口可正常访问。

<PrepareIOS />

### 启动 Playground

无需编写代码，即可通过 Playground 快速验证设备截图、触控输入与模型调用是否正常：

1. 在终端运行以下命令启动 iOS Playground：

```bash
npx --yes @midscene/ios-playground
```

2. 在自动打开的 Playground 页面中，点击右上角的齿轮图标，粘贴你的模型 API Key 配置并保存（配置格式见[配置模型 API Key](../model-api-setup)）。
3. 若浏览器未自动打开，请手动访问终端打印的本地地址，并保持该终端窗口持续运行。
4. 若页面弹出连接面板，请填写 WDA 的主机地址与端口（本机默认为 `localhost` 和 `8100`）并创建 Agent（若本机默认端口上的 WDA 已就绪，Playground 可能会自动完成连接；若通过网关代理访问 WDA，请填写完整的 **WebDriverAgent base URL**，切勿同时填写 host / port）。
5. 确认预览区域已正常显示当前设备或模拟器的屏幕画面；若画面未显示，请先排查 WDA 连接与端口转发。

### 执行操作并验证结果

在 iOS 设备或模拟器上打开 Safari 浏览器，跳过首次启动引导，访问 [TodoMVC](https://todomvc.com/examples/react/dist/#/)，并保持设备解锁且浏览器位于前台。

1. 在 Playground 中选择 `aiAct`，输入以下指令并运行：

```text
添加一个名为“体验 Midscene”的待办事项，然后将它标记为已完成。
```

2. 待页面中出现已勾选完成的待办事项后，切换到 `aiAssert`，输入以下断言并运行：

```text
列表中存在名为“体验 Midscene”的待办事项，且它已被标记为完成。
```

3. 确认断言执行通过，并在结果面板中查看各步骤的截图与执行过程。至此，WDA 连接、屏幕截图、触控输入和模型调用均已验证完毕。

如果执行失败，请结合报错信息排查：若无画面或无法操控设备，请查看下方的「常见问题」；若模型请求报错，请参考[模型连接检查](../model-config#verify-model-connectivity)。

## 下一步

完成环境与 Playground 验证后，可根据使用场景选择接入方式：

- **编写 YAML 测试**：通过 [Midscene Test](../midscene-test/use) 初始化项目、运行测试用例并查看报告。
- **接入现有 JavaScript 测试**：[接入 Vitest](../sdk/vitest)。
- **编写独立自动化脚本**：阅读[编写独立自动化脚本](../sdk/standalone)，参考对应平台的完整代码示例。
- **查阅平台 SDK 接口**：阅读 [iOS JavaScript SDK](../sdk/ios)，了解构造参数、平台专属方法与生命周期管理。

注意：在 Playground 界面中填写的模型配置仅保存在本地浏览器中，不会自动同步到测试或脚本进程。接入工程时，请将验证通过的模型配置写入项目的 `.env` 文件并按文档说明加载，同时保持 WDA 服务与端口转发处于可用状态。

## 常见问题

### 为什么 WebDriverAgent 已连接，但仍无法控制真机设备？

请依次检查真机上的以下设置：

1. **开发者模式**：在系统「设置 > 隐私与安全性 > 开发者模式」中确认已开启并重启生效。
2. **UI Automation**：在系统「设置 > 开发者 > Enable UI Automation」中确认已开启。
3. **电脑信任授权**：重新插拔 USB 数据线，确保已在手机弹窗中点击「信任此电脑」。

### iOS 模拟器与真机在使用上有哪些区别？

| 特性 | iOS 真机 | iOS 模拟器 |
| --- | --- | --- |
| 端口转发 | 需要运行 `iproxy` | 不需要（直接监听本机端口） |
| 开发者模式 | 需手动开启并重启手机 | 默认开启 |
| UI Automation 开关 | 需在「设置 > 开发者」中手动开启 | 默认开启 |
| 运行性能 | 真实硬件性能 | 取决于宿主机 Mac 性能 |
| 硬件传感器 | 真实传感器 | 模拟数据 |

### 如何自定义 WebDriverAgent 的端口和主机地址？

请参阅 [iOS JavaScript SDK](../sdk/ios#如何自定义-webdriveragent-的端口和主机地址)。

### 如何在 Playground 中获得更流畅的实时投屏画面？

iOS Playground 的屏幕预览支持两种模式：

- **截图轮询模式**（默认）：逐帧调用 WDA 截图接口，帧率约为 5～10 fps。
- **原生 MJPEG 流模式**（推荐）：直接接入 WDA 内置的 MJPEG Server，帧率更高且延迟更低。

在真机上启用原生 MJPEG 流时，需额外将设备的 `9100` 端口（WDA MJPEG 默认端口）转发到 Mac 本机（模拟器无需转发）：

```bash
iproxy 9100 9100 YOUR_DEVICE_ID
```

Playground 启动时会自动探测本机 `9100` 端口：若端口可用，终端会输出 `MJPEG: streaming via native WDA MJPEG server` 并启用实时流；若不可用，则自动回退为截图轮询模式。
