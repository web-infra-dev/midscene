# Integrate with Playwright Test

With `PlaywrightAiFixture`, you can use Midscene's visual interaction and assertion capabilities directly in an existing Playwright Test project. Playwright Test organizes and runs the tests, while Midscene interacts with the page and generates execution reports.

## Further configuration

### Agent options {#agent-options}

Pass Agent options when creating the fixture:

```typescript title="e2e/fixture.ts"
import { test as base } from '@playwright/test';
import {
  PlaywrightAiFixture,
  type PlayWrightAiFixtureType,
} from '@midscene/web/playwright';

export const test = base.extend<PlayWrightAiFixtureType>(
  PlaywrightAiFixture({
    waitForNetworkIdleTimeout: 2000,
    replanningCycleLimit: 30,
  }),
);
```

You can also pass other Agent options such as `waitAfterAction` and `modelConfig`. Test and report metadata (`testId`, `reportFileName`, `groupName`, and `groupDescription`) are automatically derived from the current test info and do not need to be set manually. See [Playwright SDK configuration](./sdk/playwright#web-options) for platform options and [shared Agent options](./reference/#agent-options) for common settings.

### Work with a specific page

The AI methods injected by the fixture operate on Playwright's default `page` fixture. To interact with another `Page` instance in the same test (such as one created via `context.newPage()`), use `agentForPage` to get the corresponding Agent:

```typescript
import { test } from './fixture';

test('inspect another page', async ({ context, agentForPage }) => {
  const page = await context.newPage();
  await page.goto('https://todomvc.com/examples/react/dist/');

  const agent = await agentForPage(page);
  await agent.aiAssert('The page contains a todo input');
});
```

For details on new tabs and navigation behavior, see [Web / Playwright SDK](./sdk/playwright#about-opening-in-a-new-tab).

### Lifecycle

Within a test, the fixture creates one Agent per `Page` and reuses it across AI calls. When a page closes or the test finishes, the fixture automatically calls `agent.destroy()` and collects the report, so you do not need to destroy fixture-managed Agents manually. Browser contexts and pages remain managed by Playwright.

If you bypass the fixture and instantiate an Agent directly with `new PlaywrightAgent(page)`, you must call `agent.destroy()` yourself; see [Lifecycle and resource ownership](./sdk/standalone#lifecycle-and-resource-ownership).

### Report options

Pass options to the reporter in `playwright.config.ts`:

```typescript
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [
    ['list'],
    ['@midscene/web/playwright-reporter', {
      type: 'merged',
      outputFormat: 'single-html',
    }],
  ],
});
```

- `type`: `'merged'` (default) combines all tests into a single report; `'separate'` generates a separate report for each test.
- `outputFormat`: `'single-html'` (default) embeds execution data and screenshots in one HTML file for offline viewing; `'html-and-external-assets'` stores execution data and screenshots as external files.

When using `'html-and-external-assets'`, keep the HTML file and its asset directory in their relative paths, and preview the report through a local HTTP server (opening it directly via `file://` is not supported):

```bash
pnpm dlx serve midscene_run/report
```

Then open the URL printed in the terminal. When sharing or archiving the report, include both the HTML file and its asset directory.

For a complete working project, see the [Playwright Test example](https://github.com/web-infra-dev/midscene-example/tree/main/playwright-testing-demo).
