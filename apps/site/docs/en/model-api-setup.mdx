# Use a model API key

Connect Midscene using an API key from a model provider. This guide covers model configuration and connection verification. If you already have a ChatGPT subscription, you can also follow [Use a ChatGPT subscription](./chatgpt-subscription).

The model configuration shown on this page consists of environment variables. Provide it according to how you use Midscene:

- In Playground, paste the configuration text from this page directly into the settings page.
- With the SDK or CLI, load the configuration as described in [Set environment variables](#set-environment-variables).

For advanced parameter definitions, see [Model advanced configuration and debugging](./model-config).

## Supported models

For an overview of supported models and connection methods, see the [Model Selection Guide](./model-selection). Configuration examples for each model follow.

Each configuration requires a Base URL, API key, model name, and `MIDSCENE_MODEL_FAMILY`. The model family (`MIDSCENE_MODEL_FAMILY`) selects the model adapter, which determines coordinate handling, supported API protocols, and how reasoning and output parameters are sent. Use the family listed for your model below.

**Enable Fast mode (`service_tier="fast"`)**

Both GPT-5.6 Sol and GPT-6 Astra support Fast mode. Add the `service_tier` request body parameter to enable it. For example, with GPT-5.6 Sol:

```bash
MIDSCENE_MODEL_NAME="gpt-5.6-sol"
MIDSCENE_MODEL_FAMILY="gpt-5"
MIDSCENE_MODEL_EXTRA_BODY_JSON='{"service_tier":"fast"}'
```

According to OpenAI, Fast mode can deliver up to 2–2.5× the speed at twice the Standard rate. Refer to the [official documentation](https://developers.openai.com/api/docs/guides/fast-mode) for current speed, pricing, and usage restrictions.


To reuse a Codex CLI session, see [Use Codex App Server](./chatgpt-subscription#use-codex-app-server-oauth-no-api-key).

**When using GPT, note the following:**

- GPT-5.4 or later is required for UI localization. Midscene does not support earlier versions.
- According to OpenAI, GPT-5 may still struggle with non-Latin text and with text that is too small in the image. See the [Images and Vision guide](https://developers.openai.com/api/docs/guides/images-vision).
- In the computer use guide, OpenAI says they observe good performance around `1440x900` and `1600x900`. We recommend adjusting screenshot sizes accordingly. In Midscene, you can control screenshot compression with `screenshotShrinkFactor` in the agent options. For browser automation, you can also control the page size and scale through the browser `viewport`.
- Azure OpenAI's Chat Completions API may not handle `"detail": "original"` correctly, causing click-coordinate offsets. If you encounter this issue, you can switch to the Responses API. See [Clicks are offset when using Azure OpenAI](./faq#clicks-are-offset-when-using-azure-openai).

### Jev (experimental) {#jev}

<details>
<summary>View model configuration</summary>

Jev is a model for making choices. You can use it to select the next action, locate UI elements, and evaluate whether a condition holds. It is fast and inexpensive, but is not suitable for tasks that require complex reasoning.

Midscene support for Jev is experimental.

- Model provider: [TypeSafe](https://typesafe.ai/)

**First configure a general-purpose default model (`MIDSCENE_MODEL_*`) and keep that configuration, then add the Jev configuration below.** Jev handles Planning, Locate, and Insight; the general-purpose default model still handles tasks Jev cannot perform. See [Multiple models](./model-config#multi-model-combination-example) for default model configuration.

Copy the following configuration to use Jev for Planning, Locate, and Insight:

<ModelConfigCard
  baseUrl={{
    value: "https://api.typesafe.ai/v1",
    comment: "TypeSafe official API endpoint",
  }}
  modelName="jev-1.14.0"
  modelFamily="jev"
  layout="combined"
  purposes={['planning', 'locate', 'insight']}
/>

Jev uses TypeSafe's System One protocol, not an OpenAI protocol. Some OpenAI model settings do not apply, such as temperature, native reasoning, response format, and streaming output.

:::info Image input limits

Jev requires the longest edge of an input image to be no more than 1568 pixels. Midscene therefore scales images that exceed this limit while preserving their aspect ratio, then maps localization results back to the original image coordinates. Edges shorter than 280 pixels are padded. This image processing behavior may change in future versions.

:::

</details>

## Set environment variables

Midscene reads model configuration from environment variables. Choose the method that matches how you use Midscene, or keep using your project's existing environment-management approach.

### Set environment variables in the current shell

The following example works in Bash and Zsh. These variables are available only to the current shell session and its child processes.

```bash
# Replace every value with the configuration for your selected model provider
export MIDSCENE_MODEL_BASE_URL="https://replace-with-your-model-service-url/v1"
export MIDSCENE_MODEL_API_KEY="replace-with-your-api-key"
export MIDSCENE_MODEL_NAME="replace-with-your-model-name"
export MIDSCENE_MODEL_FAMILY="replace-with-the-family-for-your-model"
```

### Configure through a `.env` file

Midscene Test (`@midscene/test`) and the [legacy YAML script runner](./yaml-script-runner) (`@midscene/cli`) automatically load configuration from `.env`.

For Midscene Test, copy `.env.example` to `.env` in the generated test project directory, fill in the model configuration, then run `pnpm test`. See [Create and use test projects](./midscene-test/use) for details. For the legacy YAML script runner, create `.env` in the directory where you run `midscene`.

Example `.env` contents:

```bash
# Replace every value with the configuration for your selected model provider
MIDSCENE_MODEL_BASE_URL="https://replace-with-your-model-service-url/v1"
MIDSCENE_MODEL_API_KEY="replace-with-your-api-key"
MIDSCENE_MODEL_NAME="replace-with-your-model-name"
MIDSCENE_MODEL_FAMILY="replace-with-the-family-for-your-model"
```

Do not add `export` at the beginning of each line. With the legacy YAML script runner, existing shell variables take precedence over matching values in `.env`; use `--dotenv-override` to prefer values from the file.

:::info JavaScript SDK

The Midscene SDK reads model configuration from `process.env`. When writing test scripts, you can install [dotenv](https://www.npmjs.com/package/dotenv) in your own test project, store model configuration in a `.env` file at the project root, and add `import 'dotenv/config'` to your script entry point. Run the script from the project root and load the configuration before creating an Agent.

:::

## Other compatible models

The following smaller models are also compatible with Midscene and designed for automation. They require less deployment hardware but may struggle with complex tasks or large screenshots. Evaluate them against your tasks and deployment constraints before choosing one.

### Zhipu AutoGLM Series {#auto-glm}

<details>
<summary>View model configuration</summary>

Zhipu AutoGLM is an open-source mobile UI automation model (9B parameters) from Zhipu AI.

After obtaining an API key from [Z.AI (Global)](https://z.ai/manage-apikey/apikey-list) or [BigModel (CN)](https://bigmodel.cn/usercenter/proj-mgmt/apikeys), configure:

```bash
MIDSCENE_MODEL_BASE_URL="https://api.z.ai/api/paas/v4" # Or https://open.bigmodel.cn/api/paas/v4
MIDSCENE_MODEL_API_KEY="......"
MIDSCENE_MODEL_NAME="autoglm-phone"
MIDSCENE_MODEL_FAMILY="auto-glm" # Or "auto-glm-multilingual"
```

**About `MIDSCENE_MODEL_FAMILY` Configuration**

AutoGLM provides two model versions, distinguished by `MIDSCENE_MODEL_FAMILY`:

- `auto-glm` - Corresponds to AutoGLM-Phone-9B, optimized for **Chinese mobile applications**
- `auto-glm-multilingual` - Corresponds to AutoGLM-Phone-9B-Multilingual, supports **English and other languages**

Choose the appropriate version based on your application language.

:::info
AutoGLM is best suited for mobile interaction. APIs such as `aiAssert` and `aiQuery` require page understanding. When using these APIs, configure a separate Insight model with the `MIDSCENE_INSIGHT_MODEL_...` environment variables. See [Model Selection Guide](./model-selection) for details.
:::

**Learn more about Zhipu AutoGLM**

- Github: [https://github.com/zai-org/Open-AutoGLM](https://github.com/zai-org/Open-AutoGLM)
- Hugging Face: [https://huggingface.co/zai-org/AutoGLM-Phone-9B](https://huggingface.co/zai-org/AutoGLM-Phone-9B)

</details>

### UI-TARS Series {#ui-tars}

<details>
<summary>View model configuration</summary>

Use the deployed `doubao-1.5-ui-tars` on [Volcano Engine](https://volcengine.com):

```bash
MIDSCENE_MODEL_BASE_URL="https://ark.cn-beijing.volces.com/api/v3"
MIDSCENE_MODEL_API_KEY="...."
MIDSCENE_MODEL_NAME="ep-2025..." # Inference endpoint ID or model name from Volcano Engine
MIDSCENE_MODEL_FAMILY="vlm-ui-tars-doubao-1.5"
```

**About `MIDSCENE_MODEL_FAMILY`**

This variable selects the UI-TARS version. Supported values:
- `vlm-ui-tars` – for the 1.0 release
- `vlm-ui-tars-doubao` – for the 1.5 release deployed on Volcano Engine (equivalent to `vlm-ui-tars-doubao-1.5`)
- `vlm-ui-tars-doubao-1.5` – for the 1.5 release deployed on Volcano Engine

:::info

The legacy configurations `MIDSCENE_USE_VLM_UI_TARS=DOUBAO` or `MIDSCENE_USE_VLM_UI_TARS=1.5` are still supported but deprecated. Please migrate to `MIDSCENE_MODEL_FAMILY`.

Migration mapping:
- `MIDSCENE_USE_VLM_UI_TARS=1.0` → `MIDSCENE_MODEL_FAMILY="vlm-ui-tars"`
- `MIDSCENE_USE_VLM_UI_TARS=1.5` → `MIDSCENE_MODEL_FAMILY="vlm-ui-tars-doubao-1.5"`
- `MIDSCENE_USE_VLM_UI_TARS=DOUBAO` → `MIDSCENE_MODEL_FAMILY="vlm-ui-tars-doubao"`

:::

</details>
