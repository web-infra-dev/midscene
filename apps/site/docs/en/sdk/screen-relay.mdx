# Screen Relay JavaScript SDK

`@midscene/screen-relay` provides `ScreenRelayDevice` and `ScreenRelayAgent` for automating desktops exposed via [`screen-relay`](https://github.com/vercel-labs/screen-relay). `ScreenRelayAgent` inherits all [AI methods](../reference/#interaction-methods) from the base `Agent`. See [Screen Relay environment setup](../platforms/screen-relay) to start `screen-relay`.

## Imports

```typescript
import {
  ScreenRelayAgent,
  ScreenRelayDevice,
  ScreenRelayMidsceneTools,
  agentForScreenRelay,
} from '@midscene/screen-relay';
```

## `agentForScreenRelay()`

```typescript
agentForScreenRelay(options?: AgentForScreenRelayOpt): Promise<ScreenRelayAgent>
```

Creates and connects a `ScreenRelayDevice`, then returns a `ScreenRelayAgent`. `options` accepts both [shared Agent options](../reference/#agent-options) and `ScreenRelayDevice` options. Passing the full Viewer URL with `#token=...` in `url` extracts the token automatically.

```typescript
import { agentForScreenRelay } from '@midscene/screen-relay';

const agent = await agentForScreenRelay({
  url: 'http://127.0.0.1:8080/#token=<your-token>',
});

try {
  await agent.aiAct('Open a terminal and run echo hello');
  await agent.aiAssert('The terminal displays hello');
} finally {
  await agent.destroy();
}
```

## `ScreenRelayDevice` / `ScreenRelayAgent`

```typescript
new ScreenRelayDevice(options?: ScreenRelayDeviceOpt)
new ScreenRelayAgent(device, options?)
```

When constructing them separately, call `await device.connect()` before creating `ScreenRelayAgent`:

```typescript
const device = new ScreenRelayDevice({
  url: 'http://127.0.0.1:8080',
  token: process.env.MIDSCENE_SCREEN_RELAY_TOKEN,
});
await device.connect();

const agent = new ScreenRelayAgent(device);
```

## Configuration options

Both `agentForScreenRelay()` and `new ScreenRelayDevice()` accept:

- `url?: string` — Server URL or full Viewer URL (supports `#token=` and `?token=`). Default: `process.env.MIDSCENE_SCREEN_RELAY_URL` or `'http://127.0.0.1:8080'`.
- `token?: string` — Session token (overrides any token embedded in `url`). Default: token parsed from `url`, or `process.env.MIDSCENE_SCREEN_RELAY_TOKEN`.
- `timeoutMs?: number` — Per-request timeout in milliseconds (finite positive number). Default: `15000`.
- `customActions?: DeviceAction<any>[]` — Custom actions registered for the Agent planner. See [Integrate with any interface](../integrate-with-any-interface).

## `device.getCapabilities()`

```typescript
device.getCapabilities(): ScreenRelayCapabilities | undefined
```

Returns the capability descriptor fetched during `connect()` (backend name, screen size, clipboard, IME, and supported input types). `ScreenRelayDevice` automatically prunes unsupported actions from `actionSpace()` based on these flags.

## CLI

```bash
export MIDSCENE_SCREEN_RELAY_URL="http://127.0.0.1:8080"
export MIDSCENE_SCREEN_RELAY_TOKEN="<your-token>"

npx @midscene/screen-relay connect
npx @midscene/screen-relay capabilities
npx @midscene/screen-relay act --prompt "Click the Search box and type hello"
npx @midscene/screen-relay take_screenshot
npx @midscene/screen-relay disconnect
```

Pass the token via `MIDSCENE_SCREEN_RELAY_TOKEN` to keep it out of shell history and process arguments; `--token` and `#token=` passed on the command line are redacted from CLI debug logs.

## Lifecycle

```typescript
agent.destroy(): Promise<void>
```

Each `ScreenRelayDevice` instance belongs to a single `Agent`. Do not share one `ScreenRelayDevice` across multiple Agents or reuse it after `destroy()`.

Calling `await agent.destroy()` invokes `device.destroy()` and finalizes the execution report. It only clears local client state and does not stop the remote `screen-relay` daemon or desktop applications. To reconnect, call `agentForScreenRelay()` again or create a new `ScreenRelayDevice`.
