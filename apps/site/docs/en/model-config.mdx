## Required settings

You need to set a default model for Midscene; see [Model strategy](./model-strategy) for details.


| Name | Description |
|------|-------------|
| `MIDSCENE_MODEL_API_KEY` | Model API key for OpenAI-compatible HTTP providers, e.g., `"sk-abcd..."`. Not required when `MIDSCENE_MODEL_BASE_URL="codex://app-server"`; see [Use Codex App Server](./model-common-config#use-codex-app-server-oauth-no-api-key) |
| `MIDSCENE_MODEL_BASE_URL` | API endpoint URL, usually ending with a version (e.g., `/v1`); do not append `/chat/completion` here since the underlying sdk will add it automatically |
| `MIDSCENE_MODEL_NAME` | Model name |
| `MIDSCENE_MODEL_FAMILY` | Model family, determine the way of dealing with the coordinates |

## Advanced settings (optional)

If you configure a dedicated Insight or Planning model, model-related `MIDSCENE_MODEL_*` settings in this section only take effect for the Insight or Planning intent when you configure the corresponding `MIDSCENE_INSIGHT_MODEL_*` or `MIDSCENE_PLANNING_MODEL_*` setting.

| Name | Description |
|------|-------------|
| `MIDSCENE_MODEL_TIMEOUT` | Hard timeout per AI API request in milliseconds (default intent). Defaults to `180000` (180 seconds). Covers the full request lifetime, including reading the response body. Each retry starts a fresh timeout using the same configuration; retry delays are excluded, so the total call duration may exceed this value. Set to `0` to disable only the Midscene hard timeout. SDK and underlying network timeouts may still apply, and callers can cancel requests with an `AbortSignal`. |
| `MIDSCENE_MODEL_TEMPERATURE` | Sampling temperature for model responses |
| `MIDSCENE_MODEL_RETRY_COUNT` | Number of retries when AI call fails, default 1 (i.e., retry once after failure). Retries occur when the model request encounters an HTTP error or when the model response cannot be structurally parsed |
| `MIDSCENE_MODEL_RETRY_INTERVAL` | Interval between retries in milliseconds, default 2000 |
| `MIDSCENE_MODEL_REASONING_ENABLED` | Controls whether model-native thinking is enabled. Midscene disables it by default. See [Model-native thinking](#model-native-reasoning) |
| `MIDSCENE_MODEL_REASONING_EFFORT` | Controls model-native thinking effort, supported by some models. Common values: `low`, `medium`, `high`. See [Model-native thinking](#model-native-reasoning) |
| `MIDSCENE_MODEL_REASONING_BUDGET` | Thinking token budget (number), supported by some models. See [Model-native thinking](#model-native-reasoning) |
| `MIDSCENE_MODEL_RESPONSE_FORMAT` | Structured response strategy: `auto` (default) lets Midscene automatically use `response_format` in appropriate scenarios to specify a structured output format (usually JSON), making the model response as suitable for structured parsing as possible; `none` does not set `response_format`, for models that do not support structured output. |
| `MIDSCENE_MODEL_HTTP_PROXY` | HTTP/HTTPS proxy, e.g., `http://127.0.0.1:8080` or `https://proxy.example.com:8080`. Takes precedence over `MIDSCENE_MODEL_SOCKS_PROXY` |
| `MIDSCENE_MODEL_SOCKS_PROXY` | SOCKS proxy, e.g., `socks5://127.0.0.1:1080` |
| `MIDSCENE_MODEL_INIT_CONFIG_JSON` | JSON blob that overrides the OpenAI SDK initialization config. Use `defaultHeaders` for custom auth headers; `extra_headers` and `extraHeaders` are accepted as aliases |
| `MIDSCENE_MODEL_EXTRA_BODY_JSON` | JSON blob merged into each chat completion request body. Unlike `MIDSCENE_MODEL_INIT_CONFIG_JSON` (which configures the SDK client), this is spread into every `completion.create()` call sent to the model, e.g. enabling thinking mode in vLLM: `'{"chat_template_kwargs":{"enable_thinking":true}}'` |

> Note: Control replanning behavior with the agent option `replanningCycleLimit` (defaults to 20, or 40 for `vlm-ui-tars`), not with environment variables.

### Independent Planning memory and log controls

These settings apply to the standard `aiAct` planner. Both default to enabled, independently of `deepThink: false`, `true`, or `'auto'`.

| Name | Description |
|------|-------------|
| `MIDSCENE_PLANNING_MEMORY` | `true` (default) enables the `<memory>` prompt, memory storage, and recall. `false` disables these and removes unsolicited `<memory>` output from subsequent assistant history. |
| `MIDSCENE_PLANNING_LOG` | `true` (default) enables model `<log>` preambles and cumulative action execution results in subsequent planning requests. `false` disables both and removes unsolicited `<log>` output from subsequent assistant history. Fast effort keeps its action-derived display labels rather than requesting model preambles. |

Both accept `true`/`false` or `1`/`0` (case-insensitive). Values are read once at the start of each `aiAct` call, before Auto classification; invalid values and explicit use with custom planning adapters throw an error. Original model responses and action records remain in reports. Error feedback and action outputs needed by the next planning step remain available when log is disabled.

DeepThink continues to control sub-goals; it no longer enables or disables memory or log. The default Locate strategy remains unchanged. In particular, `MIDSCENE_PLANNING_SEPARATE_LOCATE` continues to control independent Locate calls.

```ini
MIDSCENE_PLANNING_MEMORY=true
MIDSCENE_PLANNING_LOG=false
```

### Task scope and planning screenshots

| Name | Description |
|------|-------------|
| `MIDSCENE_PLANNING_TASK_SCOPE` | `true` (default) includes the existing task-scope guidance about exact instructions, intermediate states, and avoiding extra actions. `false` omits those passages, without removing the user instruction or other completion rules. Accepts `true`/`false` or `1`/`0` (case-insensitive). |
| `MIDSCENE_PLANNING_SCREENSHOT_COUNT` | Accepts only `1` or `2`, limiting execution screenshots per Planning request, including the current screenshot. `1` means current only; `2` means current plus the most recent historical screenshot. Reference images are separate. The first round has only the initial screenshot. These match the previous single-screenshot (DeepThink off) and before/after (DeepThink on) behaviors, but an explicit value does not toggle DeepThink. |

Both settings are captured once before Auto classification and apply only to the standard planner. Invalid values and explicit use with custom planning adapters throw an error. An unset or empty screenshot count preserves the existing limit: two for DeepThink, one otherwise. An explicit count overrides that limit in every mode. Plan records include the effective task-scope flag and screenshot limit.

All standard planning modes allow navigation needed to fulfill the task, while respecting explicit instructions to stay on the current page. Disabling TaskScope does not grant permission for unrequested actions.

Auto defaults to enabling DeepThink and disables it only when the task clearly does not need explicit sub-goal tracking. The task description is the primary evidence, user context supplements it, and screenshots are secondary. Known values or independent edits do not by themselves justify disabling it: forms and repeated edits can still require coverage and constraint tracking. Uncertainty keeps DeepThink enabled. This remains a single decision at task start, not runtime switching or a change to model-native reasoning.

```ini
MIDSCENE_PLANNING_TASK_SCOPE=true
MIDSCENE_PLANNING_SCREENSHOT_COUNT=2
```

### Model-native thinking {#model-native-reasoning}

Midscene disables model-native thinking by default for better execution speed and stability. If a model cannot disable native thinking, Midscene reduces it as much as possible by controlling the thinking granularity or budget.

The following environment variables provide a unified Midscene abstraction over provider-specific parameters. The parameters sent to the model depend on `MIDSCENE_MODEL_FAMILY`.

`MIDSCENE_MODEL_REASONING_ENABLED` explicitly controls whether model-native thinking is enabled:

- `false`: Force-disable model-native thinking. This is the Midscene default.
- `true`: Force-enable model-native thinking.
- `default`: Follow the model's default behavior. Midscene does not send a parameter that enables or disables thinking, and it ignores explicit `MIDSCENE_MODEL_REASONING_BUDGET` and `MIDSCENE_MODEL_REASONING_EFFORT` settings.

The following model families currently support `MIDSCENE_MODEL_REASONING_ENABLED`:

- Qwen: Maps to `enable_thinking`.
- Doubao: Maps to `thinking.type`.
- DeepSeek: Maps to `thinking.type`.
- Zhipu GLM: Maps to `thinking.type`.
- GPT-5: Maps to `reasoning_effort`. Midscene uses `medium` when enabled and `none` when disabled.
- Gemini: Maps to `thinking_config.thinking_level`. Midscene uses `medium` when enabled and `minimal` when disabled.
- Kimi K2 series: Maps to `thinking.type`.
- Xiaomi MiMo: Maps to `thinking.type`.

`MIDSCENE_MODEL_REASONING_BUDGET` controls the thinking budget. Qwen currently supports this setting through `thinking_budget`.

`MIDSCENE_MODEL_REASONING_EFFORT` controls thinking effort. The following model families currently support it:

- Doubao: Maps to `reasoning_effort`.
- DeepSeek: Maps to `reasoning_effort`.
- Gemini: Maps to `thinking_config.thinking_level`.
- GPT-5: Maps to `reasoning_effort`.
- Kimi K3 series: Maps to `reasoning_effort`.

Provider support and accepted values vary. See each provider's official documentation for supported model versions and values. If the current model does not support an explicit setting, Midscene ignores it instead of guessing a provider-specific private parameter.
