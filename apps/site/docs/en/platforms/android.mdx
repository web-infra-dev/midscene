# Android

Midscene connects to and controls Android devices over `adb`, supporting UI automation across native apps, hybrid apps, and system interfaces.

This guide walks you through preparing your Android environment, connecting a device, and running an action and assertion in Playground before integrating with a test runner or the JavaScript SDK.

## Get started

Install Node.js (`^20.19.0 || ^22.12.0 || >=24.0.0`), confirm that `node -v` and `npx --version` work in your terminal, and prepare your [model credentials](../model-api-setup) (you will enter them in Playground shortly).

### Prepare your Android device

Before running automation, make sure `adb` on your computer can detect and communicate with your Android device.

#### 1. Install `adb` and configure `ANDROID_HOME`

- Install `adb` via [Android Studio](https://developer.android.com/studio) or the standalone [Android command-line tools](https://developer.android.com/studio#command-line-tools-only).
- Verify that `adb` is installed:

```bash
adb --version
```

Output similar to the following confirms a working installation:

```log
Android Debug Bridge version 1.0.41
Version 34.0.4-10411341
Installed as /usr/local/bin/adb
Running on Darwin 24.3.0 (arm64)
```

- Configure the `ANDROID_HOME` environment variable as described in [Android environment variables](https://developer.android.com/tools/variables), then verify that it is set:

```bash
echo $ANDROID_HOME
```

The output should point to your installed Android SDK directory, for example:

```log
/Users/your_username/Library/Android/sdk
```

#### 2. Enable USB debugging and verify the connection

In your phone's **Developer options**, enable **USB debugging** (and **USB debugging (Security settings)** if present), then connect the phone to your computer with a USB data cable.

<p align="center">
  <img src="/images/android-usb-debug-en.png" alt="android usb debug" width="400"/>
</p>

Run the following command to verify the connection:

```bash
adb devices -l
```

Output similar to the following indicates that the device is connected and ready:

```log
List of devices attached
s4ey59	device usb:34603008X product:cezanne model:M2006J device:cezan transport_id:3
```

Troubleshooting tips:
- **Empty list**: Check your USB cable (ensure it supports data transfer), USB connection mode, and Developer options toggle.
- **`unauthorized`**: Unlock the phone screen and accept the "Allow USB debugging" prompt on the device.
- **`offline`**: Reconnect the USB cable or restart `adb`. Only proceed once the device status shows `device`.

### Launch Playground

Use Playground to verify screen capture, touch input, and model calls without writing any code:

1. Start the Android Playground CLI:

```bash
npx --yes @midscene/android-playground
```

2. In the Playground window that opens, click the gear icon in the top-right corner, paste your model API key configuration, and save (see [Configure a model API key](../model-api-setup) for format details).

![](/images/android-set-env.png)

3. If your browser does not open automatically, visit the local Playground URL printed in the terminal, and keep the terminal process running.
4. In the connection panel on the left, select your target **ADB device** and create the Agent (if multiple devices are connected, match the device ID against `adb devices -l`).
5. Confirm that the preview area displays your phone's current screen. If no screen appears, check the USB connection and screenshot permissions first.

### Run an action and verify the result

On your Android device, open the browser app, complete any first-run prompts, and navigate to [TodoMVC](https://todomvc.com/examples/react/dist/#/). Keep the device unlocked with the browser in the foreground.

1. In Playground, select `aiAct`, enter the following instruction, and run it:

```text
Add a todo named "Try Midscene", then mark it as completed.
```

2. Once the completed todo item appears on the page, switch to `aiAssert`, enter the following assertion, and run it:

```text
The list contains a todo named "Try Midscene", and it is marked as completed.
```

3. Confirm that the assertion passes and inspect the step-by-step screenshots in the results panel. At this point, device connectivity, screen capture, touch input, and model calls have all been verified together.

If execution fails, check the failed step and error message: for missing screenshots or unresponsive touch input, see the [FAQ](#faq) below; for model request errors, see [Verify model connectivity](../model-config#verify-model-connectivity).

## Next steps

Once your environment and Playground are verified, choose how to integrate Midscene:

- **Write YAML tests**: Initialize a project, run test cases, and inspect reports with [Midscene Test](../midscene-test/use).
- **Integrate with existing JavaScript tests**: [Integrate with Vitest](../sdk/vitest).
- **Write standalone automation scripts**: Follow [Write standalone automation scripts](../sdk/standalone) and pick the example for your platform.
- **Look up platform SDK APIs**: See the [Android JavaScript SDK](../sdk/android) for constructor options, platform-specific methods, and lifecycle management.

Note: Model credentials entered in the Playground UI are stored locally in the browser and are not automatically shared with test or script processes. Copy your verified settings into your project's `.env` file and load them as shown in the integration guides, while keeping `adb` and device debugging permissions active.

## FAQ {#faq}

### Why can't I control the device even though it is connected (`INJECT_EVENTS` error)?

If tapping or swiping fails with a permission error like the following:

```text
Error:
Exception occurred while executing 'tap':
java.lang.SecurityException: Injecting input events requires the caller (or the source of the instrumentation, if any) to have the INJECT_EVENTS permission.
```

Some Android OEM ROMs (such as Xiaomi / MIUI / HyperOS, vivo, and OPPO) require an additional toggle in **Developer options** to allow simulated input. Make sure both of the following options are enabled:

1. **USB debugging**
2. **USB debugging (Security settings)** or **Disable permission monitoring** (if present)

### Why does scrcpy fall back to ADB screenshots?

To prevent the AI model from acting on stale frames, Midscene strictly validates scrcpy frame timestamps: any frame that cannot be proven to have been captured after the most recent completed action—or that exceeds the maximum frame age limit—is rejected. If the active scrcpy stream fails to deliver a fresh frame in time, Midscene automatically restarts scrcpy once, and falls back to `adb` screenshots only if the restarted stream also fails.

This commonly occurs when an Android hardware encoder pauses frame output on a completely static screen, or during stream startup and transient USB transport hiccups. Note that a frame-freshness warning alone does not indicate insufficient bandwidth or an excessive video bitrate—do not adjust the video bitrate solely in response to this warning.

### How do I access Android Playground remotely from another machine on the LAN?

By default, both the Playground server and its built-in scrcpy streaming server bind only to `127.0.0.1`. To access Android Playground from another computer on your network, explicitly bind both servers to a reachable interface via environment variables (for example, on macOS or Linux):

```bash
MIDSCENE_PLAYGROUND_HOST=0.0.0.0 MIDSCENE_SCRCPY_HOST=0.0.0.0 pnpm dlx @midscene/android-playground
```

Then open Playground in a browser using the host machine's LAN IP address (or hostname) and the Playground port printed at startup (note that `0.0.0.0` is a wildcard bind address, not a URL you can open in a browser), and ensure your firewall allows incoming connections on both the Playground and scrcpy ports.

`MIDSCENE_SCRCPY_HOST` applies to the standalone Android Playground CLI and can also be set to a specific local network IP (such as `192.168.1.100`, which the auto-opened local preview page will also use). If you instantiate `ScrcpyServer` directly in code, pass the `host` option to its constructor instead.

:::warning Security Notice
The scrcpy streaming server does not currently authenticate viewer sessions. Binding it to a network interface exposes device information and live screen streams to any client that can reach the port. Enable remote access only on trusted private networks and restrict access with firewall rules.
:::
