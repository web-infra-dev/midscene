# RFC：首页叙事结构调整

- 状态：草案，记录讨论方向，供后续逐块评审。
- 日期：2026-10-09。
- 范围：首页的信息组织、核心文案和展示方向。
- 文档语言：内部讨论稿使用中文；落地首页时同步中英文。

## 背景与目标

Midscene 的核心定位是：基于视觉，像人一样完成端到端（E2E）测试。

当前首页按“首屏 → 平台 → 模型策略 → 测试工具箱 → Benchmark → 用户 → 行动入口”组织。它展示了各项能力，但用户需要自行理解这些能力如何组成完整的测试流程。

新的首页需要讲清楚四件事：

1. 用自然语言表达测试意图，通过视觉完成操作与验证。
2. 视觉模型兼顾效果和低调用成本，适合频繁运行测试。
3. 同一套测试方式覆盖 Web、移动端、桌面和自定义界面。
4. 产品覆盖 GUI Agent 到 E2E 测试框架，支持整套使用、按需接入和业务扩展。

## 已确定的方向与提案边界

已确定的首屏 slogan：

> 像人一样看懂界面，用自然语言完成 E2E 测试

首屏按两行展示，品牌名 Midscene.js 独立保留：

> 像人一样看懂界面  
> 用自然语言完成 E2E 测试

讨论中明确的内容诉求包括：突出低模型调用成本、清楚表达跨端能力，以及体现从 GUI Agent 到完整测试框架的产品范围与灵活性。

下文的七个板块、次级标题和展示方式均为建议方案。除首屏 slogan 外，具体文案仍待确认。本 RFC 记录结构，不代表页面改版已经完成。

## 整体叙事顺序

**核心承诺 → 完整测试示例 → 视觉与低成本模型 → 跨端支持 → 完整产品与灵活性 → 效果与采用证据 → 开始使用。**

| 顺序 | 板块 | 回答的问题 |
| --- | --- | --- |
| 1 | 首屏定位 | 这是什么，能帮我做什么？ |
| 2 | 完整测试示例 | 我如何描述测试，又如何知道测试通过？ |
| 3 | 视觉与模型策略 | 它如何理解界面，模型调用成本如何？ |
| 4 | 跨端支持 | 能测试我的应用吗，如何接入？ |
| 5 | 完整产品与灵活性 | 如何融入已有工程，或搭建完整测试项目？ |
| 6 | 效果与实际采用 | 有哪些量化证据与真实使用案例？ |
| 7 | 开始使用 | 如何运行第一个测试？ |

## 板块设计

### 1. 首屏定位

主标题：**像人一样看懂界面，用自然语言完成 E2E 测试**。

副标题沿用当前定位：基于视觉的 GUI Agent，支持 Web、移动端和桌面应用。

核心卖点：

- **基于视觉理解界面**：解释“像人一样”的具体含义。
- **用自然语言完成 E2E 测试**：明确产品的核心用途。
- **覆盖多个平台**：让用户尽早知道产品是否适用于自己的应用。
- **免费开源**：说明软件的使用与许可方式，和模型调用费用分别表达。

展示建议：保留真实测试演示，覆盖操作与结果验证。GitHub 数据作为辅助背书。行动入口建议为“快速开始”和“查看案例”，最终名称与目标页面待确认。

### 2. 完整测试示例

建议主标题：**从一句测试意图，到可验证的执行结果**。

核心子标题：

- **自然语言描述步骤**：表达操作意图与预期结果。
- **自动执行与断言**：完成界面操作，判断结果是否符合预期。
- **查看执行报告**：回放过程，追踪每一步。

展示建议：用一个简短案例，并排展示用例、执行画面和断言结果，附完整报告入口。可以采用退款案例中的界面操作部分，与后面的工程示例保持连续。

本板块负责解释最小使用闭环。首屏视频负责吸引注意，这里负责让用户读懂输入、执行和结果的对应关系。

### 3. 视觉与模型策略

建议主标题：**视觉驱动，兼顾效果与低成本**。

核心子标题：

- **看懂界面，定位元素**：通过截图理解界面，展示 Canvas、无语义标注元素等场景。
- **低成本运行测试**：用实际任务的模型调用费用和通过率提供证据。
- **多种模型可选**：按需求选择效果与预算合适的模型。
- **多模型协同**：按需组合规划、定位和界面理解能力。

展示建议：将费用作为醒目的主视觉，模型品牌列表作为辅助信息。当前首页已有的费用案例可作为候选素材：豆包 Seed 2.1 Turbo 在 AppControlBench 的 60 项任务中通过 58 项，模型调用总费用为 $0.59。

该数字引用当前仓库首页文案，属于特定评测记录。正式展示时须核对报告，注明模型、任务范围、费用口径和来源。不能将它写成所有测试的固定价格，或整个测试工程的总成本。

本板块先讲视觉能力与成本收益，再解释模型选择和组合方式。模型名称及推荐策略以现有模型文档为准。

### 4. 跨端支持

建议主标题：**同一套测试方式，覆盖不同平台**。

核心子标题：

- **Web**：接入 Playwright、Puppeteer，或通过桥接模式驱动自己的 Chrome。
- **桌面**：测试 macOS、Windows 和 Linux 应用。
- **移动端**：覆盖 Android、iOS 和 HarmonyOS，具体设备与模拟器支持以各平台文档为准。
- **自定义界面**：通过截图与操作接口扩展接入。

展示建议：使用各平台真实运行画面，配对应接入入口。首屏概括覆盖范围，本板块展开具体支持与接入方式。

跨端独立成块，承接视觉能力，同时方便用户按平台寻找入口。“同一套测试方式”强调自然语言、API 与报告体验的一致性；跨端用例复用程度应由实际案例说明。

### 5. 完整产品与灵活性

建议主标题：**从 GUI Agent 到完整的 E2E 测试框架**。

建议引导文案：

> 用自然语言驱动界面操作与断言，用 Midscene Test 组织和运行测试。数据准备、业务接口与环境管理可通过 TypeScript 扩展，执行过程统一记录在报告与日志中。
>
> 你可以将 GUI Agent 接入现有工程，也可以使用完整框架搭建测试项目。

内部按三个层次组织：

| 产品层次 | 核心子标题 | 展示内容 |
| --- | --- | --- |
| GUI Agent | **按需使用 GUI Agent** | 自动规划完整流程，也能用 `aiTap`、`aiAssert` 等原子 API 逐步控制操作与验证；接入已有工程。 |
| Midscene Test | **组织持续运行的测试项目** | 用 YAML 和自然语言描述用例，结合生命周期钩子、并发执行与工程配置运行测试。 |
| 扩展与集成 | **用 TypeScript 扩展业务能力** | 将数据准备、业务接口和环境管理封装为自定义 Node，在 YAML 中装配调用。 |

贯穿这些层次的配套卖点：

- **统一报告与日志**：在 Midscene Test 的执行流程中追踪 AI 操作与自定义 Node，呈现入参、出参、耗时、状态及相关截图。
- **试验与排错**：通过 Playground 试验操作，通过报告回放和日志定位问题。
- **支持 AI 编程 Agent**：通过 Skills 调用 Midscene；Midscene Test 可导出当前项目注册的 Node 及参数说明，供人和 Agent 查阅。

展示建议：用退款案例串起整个测试工程。

**接口准备订单 → Agent 在界面申请退款 → AI 断言退款结果 → 清理数据 → 查看执行报告。**

让用户看到两种能力如何协作：自然语言和 YAML 表达测试意图，TypeScript 实现业务操作和工程管理。统一执行记录使两者都能被排查和维护。

此处展示完整项目，第二板块展示最小测试闭环。两处使用同一案例的不同深度，减少重复介绍。

Midscene Test 当前处于 Beta 阶段，框架入口旁应保留简洁的状态说明。具体能力边界以概述及使用文档为准。

### 6. 效果与实际采用

建议主标题：**用评测与实际案例展示能力**。

核心子标题：

- **公开评测成绩**：展示 AndroidWorld、MobileWorld 和 AppControlBench 的结果，并链接详细报告。
- **真实项目案例**：说明测试对象、接入方式和有证据支持的收益。
- **使用团队**：保留 Logo 墙，作为采用情况的辅助背书。

展示建议：先给量化评测，再给两三个有代表性的项目案例，最后展示 Logo 墙。案例素材尚待选择；仅有 Logo 时，不据此推导具体效果或收益。

模型区突出费用及对应效果，本板块展示更完整的能力证据。Benchmark 任务通过率与团队实际测试维护收益分别呈现，避免混用。

### 7. 开始使用

建议主标题：**运行你的第一个 E2E 测试**。

核心子标题：

- **快速开始**：按平台进入接入教程。
- **查看完整案例**：参考可运行的测试项目。
- **选择接入方式**：已有工程按需使用 GUI Agent，新建项目了解 Midscene Test。

展示建议：明确一个主要行动入口，再提供案例入口。平台和接入方式可在快速开始页面展开，避免首页末尾同时出现过多按钮。

## 后续落地与验收

建议先确认板块顺序与主副标题，再选定示例和评测素材，最后调整组件与视觉布局。

落地时检查：

- 首屏保留已确认的 slogan，副标题明确视觉机制与支持平台。
- 第二板块呈现输入、执行、断言和报告的对应关系。
- 模型区清晰展示低调用成本，并有匹配的模型与评测信息。
- 跨端区为各平台提供正确的文档入口。
- 产品区清楚表达“整套使用”和“按需集成”两种方式。
- 自定义 Node 与 AI 操作如何协作，有具体流程和报告支撑。
- 页面保留 Midscene Test 的 Beta 状态说明。
- 最终用户文案中英文同步，检查桌面和移动端排版。
