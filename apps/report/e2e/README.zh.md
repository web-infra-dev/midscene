# Report e2e 覆盖范围

Report e2e 使用包含真实 Agent 录制数据的报告，验证核心用户流程。配置模型凭据后运行 `pnpm --filter @midscene/report e2e`，该命令会构建报告和 CLI、生成测试数据，再执行 YAML 测试。

## 应覆盖的功能

- 加载 Agent、合并报告、旧版 YAML 和原生 Test 报告。
- 筛选、搜索、排序和展开 Project / File / Case 层级。
- 在 Case 之间跳转并保留概览状态，包括浏览器历史记录。
- 查看重试、初始化和清理失败、错误信息及 Case 累计 token 用量。
- 查看录制、截图、JSON、任务信息和运行事件。
- 使用回放、模型详情、主题切换和移动端 Steps/Player 流程。

断言应简短，描述操作后可观察的结果。定位描述应包含区分相近控件所需的上下文，例如 Replay all tasks 与单任务 Replay 标签，以及 All cases 抽屉与执行步骤列表。排序应检查结果顺序，避免依赖箭头外观。数据正确性可以使用准确的测试数据值，与这些数据的视觉排列方式无关。

保留 `aiAssert`、`aiTap`、`aiHover` 等 AI 覆盖。JavaScript 用于需要确定性检查的浏览器集成，例如历史记录和 hash 变化、焦点、原生下拉框事件，以及导航前后的数值比较。避免检查 CSS 类名、颜色、边框、间距、尺寸和截图坐标。

聚合规则、序列化上限、组件渲染和尺寸计算放在最近的单元测试中。涉及浏览器集成或用户流程时再增加 e2e。每个场景围绕一个流程，避免在不同测试文件中重复相同的导航和视觉检查。

生成的测试页面保存在被忽略的 `dist/` 中。测试运行期间应保持这些页面不变，并行构建会清空该目录。如必须并行构建，可把静态页面和 YAML 测试复制到临时目录，仅修改 `target.serve` 指向复制的页面。
