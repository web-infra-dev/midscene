# Midscene Replay

Deliver **case.yaml + steps/*.mjs**, with the native Midscene Test config when the project needs one. YAML expresses business intent; scripts implement selected `ai*` nodes. Test owns the Agent, setup, hooks, retries, results and HTML report. The coding Agent explores, designs steps, writes code, tests and repairs it. The user checks the business plan.

CLI: `../../scripts/cli.mjs` relative to this skill (or installed `midscene-replay`). Read [runtime](references/runtime-api.md), [session](references/session.md), [review](references/review.md), and [fallback](references/fallback.md) as needed. Starter files are in [templates](templates/case.yaml).

## Non-negotiable evidence and interaction

- Requirements come from the user's goal or immutable recording, not from what the candidate script happened to produce. Never weaken acceptance after a failure.
- Before first recording/execution in a task, visibly post a standalone bold **Recording data risk** notice in the user's language. Explain that unmasked screenshots, form values, page content and URLs may contain credentials/private data; name the site/output scope. Mention model screenshot transfer when planned. Do not interrupt for this notice. Reuse it for the same task/site/output/data handling; supplement only for a newly disclosed risk or recipient.
- Show a numbered business-step and acceptance table from 1, then continue. Mark it **shown**. Explicit user confirmation or correction makes it **confirmed**. Say the user can interrupt to correct it; wait only when they requested approval first or there is a real blocker.
- For login/CAPTCHA, material business ambiguity, missing credentials or real external writes, state what is needed, what the user should do, and what you will do next. For writes, show account, targets, actions and bounded planned repetitions, then obtain authorization. Reuse existing authorization within scope. A confirmed isolated/resettable test environment may authorize a bounded debugging and three-run batch together; localhost or an available reset URL alone is not proof of authorization. A shown plan is not write authorization.
- Preserve raw recordings and failed runs. Inspect actual per-step screenshots and outcomes for all three accepted runs. Program success and Agent business review are distinct; missing evidence remains unverified.

## Choose the entry, then use one workflow

| Scope | Agent explores | User records |
| --- | --- | --- |
| Existing node | `prepare-step case.yaml --case NAME --step N`; inspect the live entrance, author its implementation | Same prefix pause with `--record --out RECORDING`; user performs the target action |
| Whole workflow | Explore the target with an Agent and author YAML plus worthwhile script implementations | `record web --url URL --out RECORDING`; user performs the flow, then says done |

1. **Prepare the entrance.** Keep the existing Test project and host. For an existing step, execute the real prefix using `prepare-step`; do not fake setup by chopping YAML. The process holds the actual Agent, variables and browser until Enter ends the handoff and cleanup runs. It prints the exact target ID/CDP endpoint. A failed prefix is a failure, never a ready entrance. For manual recording from scratch, default to a new Chrome window; see session reference for login. Wait for the user's “done”, then stop the recording and immediately run `prepare RECORDING --out NEW_WORKSPACE`; read brief.md, events.jsonl and actual screenshots.
2. **Explain the plan.** Display and save goal, initial state, numbered steps, business object identity, expected result, check method and known gaps in acceptance.md. Omit pure browsing unless it reveals a later target or the user requested it. Preserve meaningful hover, input/Enter, filters and popup behavior. Each business row maps to a native YAML node; no redundant script id/title.
3. **Write.** Preserve existing prompts/options; add `replay: ./steps/name.mjs` or `{script, params}`. Use the original interpolated input via `ctx.input`; use params only for extra implementation data. Define optional ready/run/done. Separate business stages with comments and blank lines in the user's language. Keep outputs in native Test results. Current interpolation resolves project variables (${name}) and environment values (${{NAME}}) at collection; it does not reference earlier node outputs. For runtime coordination use an explicit project context/custom Node, not Replay state. There is no Replay state/results/retry/optional/recovered protocol. Default waits remain short; extend only where observed application readiness requires it.
4. **Check execution and outcomes.** Bind strict XPath to business identity, not rank. Verify guards against current DOM. Use program checks for business state and Jev `rp.verify` for visible Canvas/chart/other visual outcomes; describe positive visible evidence. Do not rewrite the application's state to make acceptance pass, or substitute direct navigation for required UI interaction. Explicitly use `rp.scrollIntoView` for known offscreen targets. Entry/done checks should establish business state without blocking an intended action locator fallback. See runtime and fallback references.
5. **Iterate through Test.** Run `midscene-test case.yaml --case NAME --replay=strict` for diagnostics. Preserve failures and inspect report events, phaseMs, named waits and heal suggestions. `auto` hands script failure back to the original ai* on the current page, including ordinary native options/cache behavior; it can repeat already-applied actions. `off` is the native comparison. Do not invent extra replay-specific retry or write gates.
6. **Verify the complete Case.** Run `verify case.yaml --case NAME --runs 3`. This freezes authored inputs and invokes native Test with strict replay and retry 0. Any source change starts a new group. Three successful full runs are required; preparation or a focused diagnostic is not full acceptance. Strict disables locator and whole-node fallback for attached scripts; explicit Jev and nodes without scripts can still use models. Exercise dynamic guard/locate variants separately under native Test auto, retaining the report; do not claim an unexercised path is verified.
7. **Review and deliver.** Open steps.md, review.png, native report links and needed original images. Record per-step/per-run pass/fail/unverified, source evidence and final business review in acceptance.md. Deliver YAML/scripts/config, daily `midscene-test ... --replay=auto`, native report links, actual initialization/step/wait/model/report costs and model requests, start-state/reset/isolation facts, and known gaps. Do not promise fixed latency or universal zero-model execution.

## Supported scope

Current strict helpers target the Web main document with Playwright/Puppeteer Agents. Native Test integration is platform-neutral; opening the YAML field does not imply mobile Replay support. No strict iframe/Shadow DOM, native dialogs or Canvas interaction support. Canvas **visual assertions** can use Jev. The dedicated browser launcher is macOS-only; other hosts can supply their own Chromium/CDP setup.
